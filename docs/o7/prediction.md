# O7 测前预测

对 Lab 2 使用的 textstats 加一项 CPU 配额。先跑无配额对照，再跑 `CPUQuota=50%`。保持相同二进制、单核绑核、`GOMAXPROCS=1`、64 KiB 文本、同一 POST `/api/analyze` 路径、相同 lbd 和默认随机种子。两轮均为 `100@30s,400@30s`。

沿用 Lab 2 的低负载测量，服务约消耗 2 ms CPU/请求。粗估 100 请求/秒需要 0.2 核，两组预计接近目标；400 请求/秒约需 0.8 核，限额组预计更常节流，并出现吞吐降低、尾延迟上升或超时。高负载下请求 CPU 成本可能变化。实测用 `cpu.max` 确认限额，用 `cpu.stat` 的节流增量和客户端逐阶段结果核对。
